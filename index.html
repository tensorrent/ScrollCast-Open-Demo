    Verification happens before the screening reaches the decoder. A changed segment cannot quietly slip through.

    The protection has a boundary.

    A granted session cannot be taken back, and no system prevents a camera pointed at a screen. Scrollcast is not a replacement for DCP/KDM, Widevine, or FairPlay.

    What this browser demo can and cannot enforce +

    The sample above verifies the publisher signature and both segment addresses before decode. Your own file is encrypted and signed with a new key in this tab. The sender preview shows the original file while ciphertext verification runs; a recipient’s file is verified and decrypted before it is displayed.

    Viewing terms are signed into the container, but a browser-only page cannot enforce them across devices. Play counts are stored in this browser and can be reset; they count successful recipient openings, with another opening required after a video ends. Different software can ignore the terms. Real ticket counting and cancellation require the hosted access server.

    A visible viewer ID is signed into the local container and displayed by this player. It is an assigned label, not an authenticated identity. It is not burned into the original or a forensic watermark: cropping, editing, or a different player can remove it. A recording is attributable only while a meaningful viewer ID remains visible.

    This page does not transcode. Use a short clip in a format your browser can play, or a JPEG/PNG image. Keep the access code: it is not included in the sealed file and cannot be recovered from it.
